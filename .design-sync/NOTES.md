# design-sync notes: BoromTech CI

- Synced to the Claude Design project "BoromTech CI": https://claude.ai/design/p/4f007695-41e9-47ae-8ba3-5e263ff1c322 (first sync 2026-10-19, 39 files, 5 components; on 2026-10-20 the job-board system was merged in: 64 files, 10 components).
- Claude Design access: run /design-login in a standalone `claude` terminal. Running it from the desktop app's chat doesn't authorize the sync.
- The synced package is `@boromtech/brand` in `design-system/brand/`: the CI's logo components plus the job-board components, re-exported from `design-system/components/src` (the job-board app's own source). The user chose on 2026-10-20 to merge the two systems with the CI as the base.
- `build.mjs` merges `tokens.json` (CI) with `../tokens.json` (job board) into `tokens.merged.json`; on a name clash the CI wins. `surface`, `line`, `ink` and `night` clash in the dark theme, so `components.css` scopes the job-board dark values back onto `.bt-btn`, `.bt-pill`, `.bt-task`, `.bt-stars` and `.bt-tier`. It also drops the job-board sheet's page-wide `body` rule and gives those roots `font-family: var(--font-sans)` and `.bt-task` its text colour instead.
- `docs/job-board/*.md` are generated by `build.mjs` from `design-system/components/<Name>/README.md` (they only add `category: Job board`). Edit the READMEs, not the copies.
- The project also holds `templates/brand-board` and `templates/logo-concepts`, made in Claude Design, not by this sync. Never delete them; the sync's delete globs don't cover `templates/`.
- Build: `node design-system/brand/build.mjs` regenerates `tokens.css` from `tokens.json`, bundles `src/` to `dist/` and emits `.d.ts`. `dist/` is gitignored, so always build before the converter.
- Converter flags: `--node-modules <repo root>/node_modules` (react, react-dom, typescript and esbuild live there, hoisted by the npm workspace) and `--entry ./design-system/brand/dist/index.js`. From a worktree, point `--node-modules` at the main checkout's `node_modules`.
- `cfg.tokensGlob` only works with `cfg.tokensPkg`; tokens ship through `cfg.cssEntry: tokens.css` instead, which also carries the Bricolage 800 `@font-face` (extracted to `fonts/`) and the Google Fonts `@import` for Bricolage Grotesque 400-700, Plex Sans Thai, Plex Sans, Plex Mono and Noto Sans SC.
- 2026-10-20: aligned with BoromTech Brand Guidelines v1.0 (navy wordmark on light grounds, `ivory` ground, `heading` role, Bricolage 700 headings and 400-600 Latin body, motion tokens, business card preview).
- Render check runs without downloading Playwright's browser: install `playwright` with `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` and set `DS_CHROMIUM_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"`.
- The wordmark outlines in `src/wordmark.ts` and `logos/*.svg` are generated by `node scripts/build-brand-logos.mjs` from the site's Bricolage Grotesque ExtraBold cut, with pen positions measured in Chrome (GPOS kerning). Rebuild them only if the font changes.
- The logo cards, `TaskCard` and `Button` use `cardMode: column` (wider than a grid cell).

## Known render warns

- `[FONT_REMOTE]` for Bricolage Grotesque (400-700 from Google), IBM Plex Sans Thai, IBM Plex Sans, IBM Plex Mono, Hiragino Sans GB and Microsoft YaHei: expected. The Plex families come from the Google Fonts `@import`; the other two are system CJK fallbacks.

## Re-sync risks

- `tokens.json` values mirror `apps/website/src/styles/site.css`. If the website palette changes, update `tokens.json` by hand; nothing checks the two against each other.
- Plex fonts load from Google Fonts at runtime (network). Only Bricolage ships as a file.
- `src/wordmark.ts` hard-codes kerning measured once in Chrome; a different Bricolage build would need re-measuring (`XS` in `scripts/build-brand-logos.mjs`).
- `scripts/build-brand-logos.mjs` imports `fontkitten`, which is only present as a transitive dependency of Astro.
- The job-board app still imports `design-system/tokens.css` and `components/bundle.css` directly. A job-board token change reaches this system on the next build, but a new clash with a CI name is silently won by the CI; check the build's `scoped dark values` line.
